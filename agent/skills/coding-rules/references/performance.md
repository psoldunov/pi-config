# Models / Context / Build Failures

- Choose fast/low-cost models for lightweight frequent calls, pairing, and workers; balanced coding models for development/orchestration; high-reasoning models for architecture, deep reasoning, and research. Follow host model availability and budget rules.
- Do not start multi-file features/refactors or complex debugging in the last 20% of context; earlier host limits win. Single-file edits, independent utilities, docs, and simple fixes are less context-sensitive.
- Complex reasoning: enable extended thinking, use host planning, critique rounds, and split-role agents where permitted. Pi thinking controls: `/thinking`, Shift+Tab, or `defaultThinkingLevel` in settings; Pi core has no built-in plan mode.
- Build failures: use available diagnostic guidance, read errors, fix incrementally, verify after each fix.
